# 相机控制系统 - UI 与 Z轴对焦模拟 (HTML/CSS/JS)

## 1. 项目简介

本项目是一个使用纯粹的 HTML, CSS, 和 Vanilla JavaScript 构建的前端应用，旨在**作为原型设计**，模拟一个工业相机控制系统的用户界面，并特别加入了**定焦相机通过移动Z轴进行自动对焦**的模拟流程。

主要功能包括：

*   仿照目标截图 (`image-1.png`) 构建的深色主题界面布局。
*   模拟相机连接/断开流程，并根据连接状态控制界面控件的可用性。
*   模拟控制面板数据的加载与显示（如序列号、配置、相机属性等）。
*   基于 Z 轴位置变化的图像清晰度模拟（通过 CSS `filter: blur()` 实现）。
*   一个完整的、包含多个阶段（初始化、请求控制权、粗扫描、精细扫描、移动定位、保存参数、释放控制权）的自动对焦流程模拟。
*   界面状态的实时反馈（连接状态、对焦状态、Z轴位置、清晰度、鼠标坐标等）。

**注意:** 本项目**主要目的为前端UI和交互流程的原型展示**，仅包含前端逻辑模拟，**不涉及任何实际的相机硬件交互、后端图像处理算法或PLC/硬件通信**。所有与硬件或后端相关的步骤均通过前端日志和延时进行模拟。

```
auto-camera/
├── index.html         # HTML 页面结构
├── styles.css         # CSS 样式定义
├── script.js          # JavaScript 逻辑与模拟
├── favicon.png        # 用于模拟相机预览的图像
├── 项目记录.md        # 开发过程中的结构总结 (可选)

```

*   `index.html`: 定义了页面的骨架，包括顶部栏、主内容区（左侧预览、右侧控制面板）和底部状态栏，并为关键元素设置了 ID 以便 JS 操作。

*   `项目记录.md`: (您之前的 Markdown 文件) 包含了从 React 版本转换到 HTML/CSS 时的 UI 结构分析。

## 3. 功能特性详解

*   **UI布局:** 严格按照截图实现，顶部固定工具栏，中间主体左侧为图像预览区，右侧为可滚动的控制面板，底部为固定状态栏。
*   **深色主题:** 使用 CSS 变量定义了一套完整的深色主题颜色方案。
*   **连接管理:**
    *   通过"连接"/"断开连接"按钮模拟与相机的连接状态。
    *   根据 `isConnected` 状态，自动启用/禁用控制面板和顶部的大部分操作按钮。
    *   连接成功后，模拟加载并填充相机信息和属性。
    *   断开连接后，清空数据并禁用控件。
*   **Z轴与清晰度模拟:**
    *   `CameraController` 类管理当前的 `currentZ` 值。
    *   `calculateClarity(z)` 方法根据当前 Z 值和预设的最佳 Z 值计算一个清晰度评分 (0-1)。
    *   `applyBlur(clarity)` 方法将清晰度评分转换为 CSS `blur()` 的像素值，应用到预览图像上。
    *   `updateUI()` 方法实时更新显示的 Z 值、清晰度值和图像模糊度。
*   **自动对焦模拟 (`startAutofocus`)**: 模拟了一个典型的自动对焦流程，包括：
    1.  **初始化/检查:** 模拟系统准备工作。
    2.  **请求Z轴控制权:** 模拟获取硬件控制。
    3.  **粗对焦:** 在预设范围内大步长扫描，记录最佳清晰度位置。
    4.  **精细对焦:** 在粗对焦峰值附近小步长扫描，确定最终最佳位置。
    5.  **(跳过)当量计算:** 仅作流程占位模拟。
    6.  **完成与切换:** 模拟移动到最佳位置、保存参数、释放控制权。
    *   使用 `async/await` 和自定义的 `wait()` 函数模拟各阶段的耗时。
    *   流程可被"停止"按钮中断。
    *   `script.js` 中的 `console.log` 详细记录了模拟的各个步骤。
*   **状态反馈:**
    *   底部状态栏显示连接状态、模拟 Z 轴位置、鼠标在预览图上的坐标、图像尺寸等。
    *   控制面板中的"对焦状态"文本会根据当前流程阶段变化，并应用不同的背景色。

## 4. 设置与运行

由于项目使用了纯粹的前端技术，不需要复杂的构建过程。

1.  **确保文件:** 确认 `index.html`, `styles.css`, `script.js`, `favicon.png` 文件都在同一个目录下。
2.  **启动 HTTP 服务器:** 因为浏览器安全策略限制，直接打开 `index.html` 文件可能无法完全正常工作（特别是如果未来涉及更复杂的API）。推荐使用一个简单的本地 HTTP 服务器来运行。
    *   **推荐方式 (需要 Python):** 在项目根目录下打开终端 (PowerShell/CMD/Bash)，运行以下命令：
        ```bash
        python -m http.server 8888
        ```
        (如果 8888 端口被占用，可以换一个，如 8000, 9000 等)
    *   **备选方式 (需要 Node.js 和 http-server):**
        ```bash
        # 如果没有安装 http-server, 先安装:
        # npm install --global http-server
        # 然后在项目根目录运行:
        http-server -p 8888 -c-1
        ```
3.  **访问页面:** 在浏览器中打开 `http://localhost:8888` (或者您选择的其他端口)。

## 5. 代码概览

*   **`index.html`:** 结构清晰，使用了语义化标签 (`header`, `main`, `section`, `aside`, `footer`)。关键交互元素都赋予了唯一的 `id`。
*   **`styles.css`:**
    *   **CSS 变量 (`:root`)**: 核心设计。所有颜色、主要间距、尺寸都定义为变量。**修改主题或整体风格应优先修改这里的变量。**
    *   **布局:** 主要使用 Flexbox 实现整体和内部布局。
    *   **样式作用域:** 尽量使用类选择器，并通过父元素类名限定作用域，减少全局污染。
    *   **状态样式:** 使用如 `.status-已对焦`, `.status-粗对焦中` 等类名来控制状态文本的外观。
*   **`script.js`:**
    *   **`CameraController` 类:** 封装了所有逻辑。
    *   **构造函数:** 获取 DOM 引用，初始化状态变量和事件监听器。
    *   **核心方法:** `connectCamera`, `disconnectCamera`, `startAutofocus`, `stopAutofocus` 等负责主要流程。
    *   **工具方法:** `calculateClarity`, `applyBlur`, `updateUI`, `updateFocusStatus`, `wait` 等提供辅助功能。
    *   **数据模拟:** `populateSimulatedData` 和 `resetUIData` 负责演示数据的填充和清除。
    *   **事件处理:** `initializeEventListeners` 统一绑定事件。

## 6. 后续修改与避免冲突建议

为了在后续开发中保持代码的整洁和可维护性，并减少样式、格式和逻辑上的冲突，请遵循以下建议：

*   **CSS 样式:**
    *   **优先使用 CSS 变量:** 添加新样式时，尽可能复用 `:root` 中定义的颜色、间距等变量。如需新颜色或尺寸，优先考虑在 `:root` 中添加新变量。
    *   **使用特定、描述性的类名:** 避免使用过于通用的类名（如 `.button`, `.input`）或直接修饰 HTML 标签（如 `button {}`, `input {}`）。为新的组件或区域创建独特的类名（例如，`.roi-control-panel`, `.calibration-settings`）。
    *   **BEM 或类似规范 (可选):** 如果项目变得复杂，可以考虑引入 BEM (Block, Element, Modifier) 命名约定，如 `.camera-controls__button--primary`，这有助于明确样式的作用域和关系。
    *   **限定作用域:** 尽可能将样式规则限定在特定的父容器内，例如 `.control-panel .button`
